### TCP 3-way handshake (port 8080)
```
Frame 1: 41052 -> 8080  [SYN]      client requests connection
Frame 2: 8080  -> 41052 [SYN, ACK] server acknowledges + agrees
Frame 3: 41052 -> 8080  [ACK]      client confirms -> connection established
```

### Unencrypted data observed
The capture contains `GET /login.php?user=admin&pass=secret123` — the **username and password are fully visible in plaintext** (see `output/http_cleartext_example.txt`). Anyone on the network path could read them.

## Why unencrypted HTTP is dangerous & how HTTPS helps
HTTP sends everything — URLs, form fields, cookies, credentials — as readable text, so any on-path attacker (rogue Wi-Fi, ARP spoofing, compromised router) can sniff or modify it. **HTTPS** wraps the session in **TLS**, encrypting the payload and authenticating the server with a certificate, so an eavesdropper sees only ciphertext and cannot tamper undetected.

## Glossary (in my own words)
- **Packet** — a small, self-contained chunk of data sent over a network, with headers (addresses, control info) + payload.
- **Protocol** — an agreed set of rules for how two systems communicate (e.g., HTTP, DNS, TCP).
- **Port** — a numbered endpoint on a host that identifies a specific service (e.g., 80=HTTP, 443=HTTPS).
- **Payload** — the actual content/data a packet carries, as opposed to its header/routing information.
- **Handshake** — the opening exchange that sets up a connection (TCP's SYN/SYN-ACK/ACK) before data flows.
